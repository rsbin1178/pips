# pips v0.1.7

**English** · [简体中文](#简体中文)

## Install

```sh
curl -fsSL https://raw.githubusercontent.com/rsbin1178/pips/main/install.sh | sh
```

The installer picks the right archive for your platform, verifies its SHA-256 against the published
`SHA256SUMS`, and refuses to install anything if the checksum does not match. Pin a version with
`PIPS_VERSION=v0.1.7`, choose the destination with `PIPS_BIN_DIR`, and set `PIPS_NO_MODIFY_PATH=1` to
keep it out of your shell rc files. Windows builds ship as a `.zip` beside the `.tar.gz`.

## Interrupted streams recover instead of dying

This is the largest change in the release. A model stream that fails or goes quiet mid-answer used to
end the turn with a fragment on screen and an error in the log. Now:

- **A stream that stops delivering bytes fails instead of parking forever.** The transport bounds the
  silence *between reads* — ten minutes by default, per adapter with `WithStreamIdleTimeout` — and
  aborts with `ai.ErrStreamIdle`. Because the bound is measured between reads and not as a total, a
  long answer is never cut short; before this, a connection that stayed open but stopped sending left
  the turn hanging with no error for any recovery layer to act on.
- **A failed stream is re-issued, not discarded.** By default the turn regenerates, so the answer you
  see is the retry's own answer rather than a glued fragment. Per-model continuation remains available
  as an opt-in, and a truncated answer is still salvaged when the provider stopped at the output limit.
- **Retries are visible while they happen,** and now also durable afterwards: each interaction records
  how many retries it needed and why, so a session file answers that question without anyone having
  watched the wait.
- **Waiting is bounded in time as well as in attempts.** The retry budget bounds the work; a
  twenty-minute episode ceiling now bounds the clock, because a provider that has gone silent can spend
  a full idle window on every attempt. The ceiling stops new attempts and never interrupts one in
  flight, so the worst case is the window plus that one attempt.
- **The provider's mid-stream error message survives.** A router in front of the Responses API nests
  the failure under `error` where the dialect puts `code` and `message` at the top level; both shapes
  are now read, so those failures arrive with their text and their class instead of an empty message.

## Terminal UI and session usage

- The transcript no longer rebuilds the Markdown engine for the whole live block on every frame, and a
  streaming repaint costs only the tail. Long sessions scroll and stream noticeably cheaper.
- `/status` gained a session usage projection: per-day buckets, per-model rows, and durations on the
  Stats page. Usage rows are priced when your config carries a `[cost]` table.
- A Models page, pointer selection for full-area list rows, a glyph instead of a header on thinking
  blocks, and a divider between Markdown table rows.

## Providers, agent and platform

- Adapters report per-request usage and provider compatibility.
- Undecodable tool arguments stay diagnosable instead of failing opaquely.
- Event payloads are validated at the boundary, and runtime context travels as a reminder.
- Append-only stores truncate by path, so a tail can be rolled back on Windows.

## Verification

- The full suite runs on macOS, Ubuntu and Windows, plus race tests over `agent` and `internal/coding`,
  the provider adapter smoke suite, `go vet`, `golangci-lint`, `govulncheck` and the core dependency
  policy check.
- The stream idle bound and the retry window were measured against a live gateway before landing: the
  largest legitimate silence observed was 4.5s to the first byte and 1.2s between chunks over 72
  streams, and a deliberately tightened 5s bound ran four live streams — one of them 22,046 events over
  88 seconds — with zero false aborts. The ceiling is documented as a ceiling, not a deadline.
- Every release runs the published installer against its own artifacts and asserts that the installed
  binary reports the tag being released.

## 安装

```sh
curl -fsSL https://raw.githubusercontent.com/rsbin1178/pips/main/install.sh | sh
```

安装脚本会按平台挑选对应的归档，用发布出来的 `SHA256SUMS` 校验 SHA-256，**校验不通过就拒绝安装**。用
`PIPS_VERSION=v0.1.7` 固定版本，用 `PIPS_BIN_DIR` 指定安装目录，用 `PIPS_NO_MODIFY_PATH=1` 避免它改动你的
shell 配置。Windows 除了 `.tar.gz` 还提供 `.zip`。

## 中断的流会恢复，而不是直接报废

这是本次最主要的改动。以前模型流在中途失败或长时间没有数据，这一轮就会留下半截答案和一条日志错误。现在：

- **连接开着但不再送字节时会失败，而不是无限期挂着。** 传输层对**相邻两次读之间**的静默设了界（默认十分钟，
  可用 `WithStreamIdleTimeout` 按适配器覆盖），超时以 `ai.ErrStreamIdle` 中止。因为这个界是按"距上一个字节"
  算而不是总时长，长回答永远不会被砍断——在此之前，这种"连接还在但不发数据"的状态会让这一轮挂着，不产生
  任何错误，任何恢复路径都无从下手。
- **流失败会重发而不是丢弃。** 默认按整段重生成，所以你看到的是重发那次的答案，而不是拼接起来的碎片；每模型
  的"续写"仍作为可选项保留，被输出上限截断的答案也仍会被抢救。
- **重试过程可见，事后也可查。** 每次交互会记录它重试了多少次、为什么重试，所以事后翻会话文件就能回答这个问题，
  不需要有人守着那段等待。
- **等待不只在次数上有界，在时间上也有界了。** 重试预算约束的是工作量；现在另有一个二十分钟的"单次重试过程"
  上界，因为一个已经不出数据的 provider 可以让每次尝试都耗掉一整个空闲窗口。上界只阻止**新的**尝试，不会打断
  已经发出的那一次，所以最坏情况是"上界 + 那一次尝试"。
- **provider 的流内错误信息不再丢失。** Responses API 前面的一层路由会把错误嵌在 `error` 下，而这个方言本身把
  `code`/`message` 放在顶层；现在两种形状都读，这类失败会带上原文与类别，而不是一条空消息。

## 终端界面与会话用量

- 转录不再每帧为整个活动块重建 Markdown 引擎，流式重绘只处理尾部，长会话的滚动与流式输出都明显更省。
- `/status` 新增会话用量投影：按天的分桶、按模型的行，Stats 页还有耗时。配置里有 `[cost]` 表时会给出金额。
- 新增 Models 页面；列表整行可点选；思考块用字形代替标题；Markdown 表格行之间加了分隔线。

## Provider、agent 与平台

- 适配器会报告每次请求的用量与 provider 兼容性。
- 工具参数无法解码时仍保留可诊断信息，而不是给一条难以理解的失败。
- 事件负载在边界处做校验，运行时上下文以提醒的形式传递。
- 仅追加的存储按路径截断，Windows 上也能回滚尾部。

## 验证

- 完整测试在 macOS / Ubuntu / Windows 三个平台运行，另有 `agent` 与 `internal/coding` 的竞态测试、provider
  适配器冒烟、`go vet`、`golangci-lint`、`govulncheck` 与核心依赖策略检查。
- 流空闲界与重试上界落地前都在真实网关上量过：72 条流里观测到的最长合法静默是首字节 4.5 秒、块间隔 1.2 秒；
  刻意收紧到 5 秒的界跑过四条真实流（其中一条 88 秒、22,046 个事件），**零次误杀**。上界在文档里就是上界，
  没有写成 deadline。
- 每次发布都会用发布出来的安装脚本装自己这一次的产物，并断言装出来的二进制报告的版本就是本次 tag。
