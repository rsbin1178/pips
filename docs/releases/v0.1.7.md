# pips v0.1.7

**English** · [简体中文](#简体中文)

## Install

macOS and Linux:

```sh
curl -fsSL https://raw.githubusercontent.com/rsbin1178/pips/main/install.sh | sh
```

Windows (PowerShell):

```powershell
irm https://raw.githubusercontent.com/rsbin1178/pips/main/install.ps1 | iex
```

Both installers download the archive for your platform, check its SHA-256 against the release's
`SHA256SUMS`, and stop if the checksum does not match. `PIPS_VERSION` pins a tag, `PIPS_BIN_DIR` sets
the destination, and `PIPS_NO_MODIFY_PATH=1` leaves shell and PATH settings alone. Windows installs to
`%LOCALAPPDATA%\Programs\pips` and adds it to the user PATH; the `.zip` and `.tar.gz` assets can also be
extracted by hand.

## Interrupted streams

A model stream that failed or stopped sending used to end the turn with a fragment on screen and an
error in the log. Four changes:

- The transport bounds the silence between reads (ten minutes by default, per adapter with
  `WithStreamIdleTimeout`) and aborts with `ai.ErrStreamIdle`. The bound is measured between reads, not
  as a total, so a long answer is not cut short. Before this, a connection that stayed open but stopped
  sending left the turn waiting with no error for any recovery path to act on.
- A stream that failed is re-issued: the default regenerates the turn, so the answer shown is the
  retry's own answer. Per-model continuation is still available, and a truncated answer is still
  salvaged when the provider stopped at the output limit.
- Retries are visible while they happen and recorded afterwards. Each interaction writes how many
  retries it needed and why, readable from the session file.
- A retry episode is bounded by wall clock as well as by attempt count: twenty minutes by default. A
  provider that has gone silent can spend a full idle window on every attempt, which the attempt budget
  alone did not bound. The ceiling stops new attempts and does not interrupt one already in flight, so
  the worst case is the window plus that attempt.

The provider's mid-stream error text is no longer lost. A router in front of the Responses API nests
the failure under `error`, where the dialect puts `code` and `message` at the top level; both shapes are
read now, so these failures arrive with their message and class instead of an empty error.

## Terminal UI and usage

- The transcript no longer rebuilds the Markdown engine for the live block on every frame, and a
  streaming repaint costs the tail.
- `/status` reports session usage: per-day buckets, per-model rows, and durations on the Stats page.
  Usage rows are priced when the config has a `[cost]` table.
- Adds a Models page, pointer selection for list rows, a glyph instead of a header on thinking blocks,
  and a divider between Markdown table rows.

## Providers, agent and platform

- Adapters report per-request usage and provider compatibility.
- Tool calls with undecodable arguments stay diagnosable.
- Event payloads are validated at the boundary, and runtime context travels as a reminder.
- Append-only stores truncate by path, so a tail can be rolled back on Windows.

## Verification

- Tests run on macOS, Ubuntu and Windows, with race tests over `agent` and `internal/coding`, the
  provider adapter smoke suite, `go vet`, `golangci-lint`, `govulncheck` and the dependency policy
  check. The install scripts are checked with `shellcheck` and the PowerShell parser.
- The stream idle bound and the retry ceiling were measured against a gateway before they landed: over
  72 streams the longest silence was 4.5s before the first byte and 1.2s between chunks. With the bound
  tightened to 5s, four live streams completed with no false abort, the longest of them 22,046 events
  over 88 seconds.
- Each release runs its own installers against the assets it just published and asserts that the
  installed binary reports the tag.

## 安装

macOS 与 Linux：

```sh
curl -fsSL https://raw.githubusercontent.com/rsbin1178/pips/main/install.sh | sh
```

Windows（PowerShell）：

```powershell
irm https://raw.githubusercontent.com/rsbin1178/pips/main/install.ps1 | iex
```

两个安装脚本都会下载对应平台的归档，用发布出来的 `SHA256SUMS` 校验 SHA-256，校验不通过就停止。
`PIPS_VERSION` 固定版本，`PIPS_BIN_DIR` 指定安装目录，`PIPS_NO_MODIFY_PATH=1` 不改动 shell 与 PATH 设置。
Windows 装到 `%LOCALAPPDATA%\Programs\pips` 并把它加入用户 PATH；`.zip` 与 `.tar.gz` 也可以自行解压。

## 中断的流

模型流失败或不再发送数据时，以前这一轮会留下半截答案和一条日志错误。这次有四处改动：

- 传输层对相邻两次读之间的静默设了界（默认十分钟，可用 `WithStreamIdleTimeout` 按适配器覆盖），超时以
  `ai.ErrStreamIdle` 中止。界按"距上一个字节"计算而不是总时长，所以长回答不会被砍断。在此之前，连接还在
  但不发数据时，这一轮会一直等下去，不产生任何错误，恢复路径无从下手。
- 失败过的流会重发：默认按整段重生成，所以看到的是重发那次的答案。每模型的续写仍可选，被输出上限截断的
  答案也仍会被抢救。
- 重试在进行时可见，事后也有记录。每次交互会写下它重试了多少次、为什么重试，可以直接从会话文件里读。
- 一次重试过程除了次数上界，还有墙钟上界（默认二十分钟）。已经不出数据的 provider 可以让每次尝试都耗掉
  一整个空闲窗口，仅靠次数预算约束不住。这个上界只阻止新的尝试，不打断已经在飞的那一次，所以最坏情况是
  "上界 + 那一次尝试"。

provider 的流内错误信息不再丢失。Responses API 前面的一层路由会把错误嵌在 `error` 下，而这个方言把
`code`/`message` 放在顶层；现在两种形状都读，这类失败会带上原文与类别，而不是一条空错误。

## 终端界面与用量

- 转录不再每帧为活动块重建 Markdown 引擎，流式重绘只处理尾部。
- `/status` 显示会话用量：按天的分桶、按模型的行，Stats 页有耗时；配置里有 `[cost]` 表时给出金额。
- 新增 Models 页面；列表整行可点选；思考块用字形代替标题；Markdown 表格行之间加了分隔线。

## Provider、agent 与平台

- 适配器报告每次请求的用量与 provider 兼容性。
- 工具参数无法解码时仍保留可诊断信息。
- 事件负载在边界处校验，运行时上下文以提醒的形式传递。
- 仅追加的存储按路径截断，Windows 上也能回滚尾部。

## 验证

- 测试在 macOS / Ubuntu / Windows 上运行，另有 `agent` 与 `internal/coding` 的竞态测试、provider 适配器
  冒烟、`go vet`、`golangci-lint`、`govulncheck` 与依赖策略检查。两个安装脚本分别用 `shellcheck` 与
  PowerShell 解析器检查。
- 流空闲界与重试上界在落地前都在真实网关上量过：72 条流里最长静默是首字节前 4.5 秒、块之间 1.2 秒。把界
  收紧到 5 秒后跑了四条真实流，没有误杀，最长的一条 88 秒、22,046 个事件。
- 每次发布都会用它自己的安装脚本安装刚发布的产物，并断言装出来的二进制报告的版本就是本次 tag。
