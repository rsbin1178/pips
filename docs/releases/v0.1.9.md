# v0.1.9

**English** · [简体中文](#简体中文)

A streaming request is now bounded in both phases that can stall: the wait for response headers, and the
silence between reads. A connection that stops answering is reported in about a minute instead of several,
and every request names the client, so an endpoint's logs can attribute the traffic.

## Install

macOS and Linux:

```sh
curl -fsSL https://raw.githubusercontent.com/rsbin1178/pips/main/install.sh | sh
```

Windows (PowerShell 5.1 or newer):

```powershell
irm https://raw.githubusercontent.com/rsbin1178/pips/main/install.ps1 | iex
```

Both check the archive against the release's `SHA256SUMS` before installing. `PIPS_VERSION` pins a tag,
`PIPS_BIN_DIR` selects the directory, and `PIPS_NO_MODIFY_PATH=1` leaves shell and PATH settings alone.

## Added

- `ai.ErrResponseTimeout`, for a streaming request that reached the endpoint but whose response headers
  never arrived. The wait is bounded at ten minutes, and the abort is replayed by the same recovery
  layers that handle a silent stream instead of parking the turn. Non-streaming calls keep no bound.

## Changed

- Every request carries `User-Agent: pips/<version>`, so an endpoint's logs can attribute the traffic. A
  build with no version reports `pips` alone. `user_agent` replaces that value per provider or model, and
  `user_agent_enabled = false` sends no `User-Agent` header at all.
- **Action required:** a gateway that filters requests by `User-Agent` now sees `pips/<version>`. Add
  `pips/` to its allowlist, or set `user_agent` to the value it expects, or the requests are refused
  before they reach the endpoint.
- A connection that stops answering is reported in about a minute instead of several. An idle HTTP/2
  connection is pinged after 30 seconds and closed when the ping goes unanswered for 10, and TCP
  keep-alive probes are set to a 30-second idle, a 10-second interval, and three probes.

## Verification

- The `ai` suite covers the new bound and the transport settings: a server that accepts a streaming
  request and never answers aborts with `ai.ErrResponseTimeout`, the abort stays inside the retryable
  classes, and a request's `User-Agent` is asserted on the server side.
- The ten-minute bound sits above the measured header wait: response headers arrived in under four
  seconds in the requests captured for this change.
- Not verified for this version yet: the release matrix, and the opt-in live-provider smoke.

## 简体中文

**简体中文** · [English](#v019)

流式请求现在在两个可能卡住的阶段都有上界：等响应头，以及两次读取之间的静默。停止响应的连接会在一分钟
左右被报出来，而不是拖上几分钟；每个请求都会表明自己的身份，端点日志因此能区分流量来源。

## 安装

macOS 与 Linux：

```sh
curl -fsSL https://raw.githubusercontent.com/rsbin1178/pips/main/install.sh | sh
```

Windows（PowerShell 5.1 及以上）：

```powershell
irm https://raw.githubusercontent.com/rsbin1178/pips/main/install.ps1 | iex
```

两者都会先用发布出来的 `SHA256SUMS` 校验归档再安装。`PIPS_VERSION` 固定版本，`PIPS_BIN_DIR` 指定安装
目录，`PIPS_NO_MODIFY_PATH=1` 不改动 shell 与 PATH 设置。

## 新增

- `ai.ErrResponseTimeout`，用于流式请求已经到达端点、但响应头始终没有到来的情况。等待上界是十分钟；中止
  后由处理静默流的同一套恢复机制重放，而不是把这一轮挂住。非流式调用仍然没有这个上界。

## 变更

- 每个请求带 `User-Agent: pips/<version>`，端点日志因此能区分流量来源。没有版本信息的构建只报 `pips`。
  `user_agent` 可按 provider 或模型替换这个值，`user_agent_enabled = false` 则完全不发 `User-Agent` 头。
- **需要操作：** 如果网关按 `User-Agent` 过滤请求，现在看到的是 `pips/<version>`。请把 `pips/` 加进白名单，
  或用 `user_agent` 设成它期望的值，否则请求会在到达端点之前被拒。
- 停止响应的连接会在一分钟左右被报出来，而不是拖上几分钟。HTTP/2 连接空闲 30 秒后会被 ping，ping 超过
  10 秒无应答就关闭；TCP 保活探针设为空闲 30 秒、间隔 10 秒、三次。

## 验证

- `ai` 测试套件覆盖了新的上界与传输设置：接受流式请求却不回应的服务端会以 `ai.ErrResponseTimeout` 中止，
  该中止仍属可重试类别；请求的 `User-Agent` 在服务端侧断言。
- 十分钟上界远高于实测的响应头等待：这次改动期间抓到的请求里，响应头都在四秒内到达。
- 本版本尚未验证的部分：发布矩阵，以及可选开启的真机 provider 冒烟。
